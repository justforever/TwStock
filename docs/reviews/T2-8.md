### Blocker

1. **`ChartStack.tsx`：十字線移動會讓四張圖表整組反覆重建（tear-down / rebuild storm），不是規格要的「重建成本可接受」而是「每次滑鼠移動都重建」**
   `web/src/components/ChartStack.tsx:28`（`maPeriods = [5, 20, 60]` 預設參數）＋ `web/src/components/ChartStack.tsx:281`（`useEffect` 的 dependency array 含 `maPeriods`）。

   `StockPage.tsx` 呼叫 `<ChartStack .../>` **沒有傳 `maPeriods`**（`web/src/pages/StockPage.tsx:290-296`），所以每次 render 都會用解構預設值重新產生一個新的 `[5, 20, 60]` 陣列字面量——JS 預設參數每次呼叫都會重新求值，這個陣列每次 render 身分都不同。
   而 `subscribeCrosshairMove` 的 handler 會呼叫 `setHoverTime(t)`（`ChartStack.tsx:249`），這會讓 `ChartStack` 重新 render；重新 render 又造出新的 `maPeriods` 陣列；`useEffect` 的依賴比較是淺比較，陣列身分不同 ⇒ **判定為「變了」**，於是整個 `useEffect` 的 cleanup（`chart.remove()` 全部）＋重建（`createChart` 全部＋`fitContent()`）又跑一次。

   實測（在既有的 `ChartStack.test.tsx` mock 環境下加一段驗證，測完即刪除，不留在 repo）：

   ```
   render 完成：charts.length === 4
   act(() => charts[0].__crosshair({ time: '2026-09-17' }))
   charts.length === 8   // 又建了 4 張新圖
   act(() => charts[4].__crosshair({ time: '2026-09-16' }))
   charts.length === 12  // 再建 4 張
   ```

   也就是**每一次十字線移動（滑鼠在主圖上滑動、正常情況下一秒可觸發數十次）都會把四張圖表全部 `remove()` 再全部重新 `createChart()`**，並且每次重建都會呼叫 `fitContent()`，使用者原本手動縮放／平移的畫面會被重置。這不是規格容許的「資料或開關變動時整組重建」（規格 §4.2：`useEffect(() => {...}, [bars, institutional, margin, showInstitutional, showMargin, maPeriods])`，本意是**資料本身沒變就不該重建**），而是因為 `maPeriods` 用了不穩定的預設參數，把「單純滑鼠移動」也算成了「資料變動」。真實瀏覽器下會造成嚴重閃爍、CPU 占用飆高，等同讓 M2 的完成標準（十字線同步）在實際使用時形同破功——`ChartStack.test.tsx` 的 mock 測試之所以沒抓到，是因為測試只斷言「crosshair handler 被呼叫」而沒有檢查重建次數，舊的 closure 仍然被直接呼叫而恰好還能通過斷言。

   **建議修法**：把預設值改成模組層級的常數（例如 `const DEFAULT_MA_PERIODS = [5, 20, 60]` 放在檔案頂部，`maPeriods = DEFAULT_MA_PERIODS` 當預設值），使其在多次 render 間身分穩定；或用 `useMemo`/`useRef` 固定陣列身分；或把 `hoverTime` 這個 state 移到不會觸發整個圖表重建 effect 的地方（例如另一個只管讀數面板的子元件／`useRef` + 手動 DOM 更新）。三者擇一即可解決。

### Minor

3. **副圖 pane 標題單位標「（張）」，實際畫的是「股」的原始值，未做 ÷1000 轉換**
   `ChartStack.tsx:364/370/377` 的標題分別是「成交量（張）」「三大法人買賣超（張）」「融資融券餘額（張）」，但 `volumeSeries` / `instSeries` / `marginSeriesBalance` 的 `setData` 直接放 `bar.volume`、`bar.total_net`、`bar.margin_balance`（皆為規格 DDL 註明的「股」，見 `docs/specs/M1-price.md:164` 與 `docs/specs/M2-chips.md` §3 `institutional_daily`／`margin_daily` 的欄位註解），沒有除以 1000。也就是圖表 Y 軸上的刻度數字會是「股」的量級（例如 3000 萬），但標題寫「張」，兩者差 1000 倍。
   讀數面板本身沒有這個問題（`toLots()` 有正確換算），只有四個副圖的 Y 軸／曲線刻度受影響。
   查對 `docs/specs/M2-chips.md` §4.1／§4.2，Architect 給的標題文字與 series 資料表本身就是這樣寫的（標題要求「張」、資料表沒要求換算），Coder 是照規格字面實作，這點建議 Architect 在下一版規格澄清：是要series 資料也除以 1000（以真正對齊「張」的標題），還是把標題改回「（股）」。本輪不算 Coder 的偏離規格，先記在這裡，不影響本輪結論。

4. M1 舊測試「顯示 2330、台積電、最新收盤 1008」被整併進新測試「預設顯示 K 線分頁與讀數面板」，斷言內容（`2330`、`台積電`）有保留，但沒有再斷言「最新收盤 1008」這個數值本身；規格要求「M1 既有的四個測試…維持通過，必要時只改選取器，不要刪掉」，這裡是重新命名＋合併，語意上還在，不影響功能正確性，記錄供參考。

### 其他檢查（無問題）

- **series 是否重複建立**：整個圖表建立與清除都包在同一個 `useEffect`／同一個 cleanup 裡，沒有另外的地方會重複呼叫 `createChart`／`addXxxSeries`；問題只在於「該不該這麼常重建」（見 Blocker 1），不是「同一次 render 裡建了兩份」。
- **十字線同步是否為真正的無限迴圈**：`setCrosshairPosition()` 是 lightweight-charts 用來『顯示』十字線的 API，呼叫它不會觸發 `subscribeCrosshairMove` 事件（該事件只在使用者滑鼠移動或 `chart.moveCrosshair` 等互動時觸發），所以 `applyCrosshairToOthers` 互相呼叫不會遞迴觸發彼此，本身不會無窮迴圈；時間軸同步已用 `syncingRef` 防重入，也沒問題。真正的問題是 Blocker 1 的「重建風暴」，性質不同但一樣嚴重。
- **副圖資料與主圖時間軸對齊**：副圖只放自己有的日期（沒有補 0），符合規格；`setVisibleLogicalRange` 用邏輯索引同步平移/縮放範圍，在法人／融資券資料筆數等於 K 線筆數時運作正常（`m2_verify.sh` 與單元測試涵蓋的都是等長情境）。規格本身承認「法人與融資券資料的時間可能少於 K 線」時只用讀數面板／籌碼分頁補位，圖表本身的邏輯索引在資料筆數不同時仍可能出現同一個索引對到不同日期的情況，這是規格既有的已知限制（§4.2 已預告），不算本任務新增的缺陷。
- **籌碼數值的單位與正負號**：`consecutiveDays`／`toLots`／`toPercent` 邏輯與規格逐條核對一致（含正負號、'—' 顯示、四捨五入位數）；`ChipTab` 的外資＝紅／up、投信/自營同樣用正負號決定顏色，語意正確；讀數面板的漲跌、外資淨額顏色也正確對應。
- **空資料與 API 失敗狀態**：`StockPage.tsx` 用 `Promise.allSettled`，`fetchStock`／`fetchPrices` 失敗才顯示 `role="alert"`，其餘四個籌碼端點失敗只 `console.warn` 並設空陣列，符合規格；`ChartStack` 在 `bars` 為空時直接 `return` 不建圖；`ChipTab` 四份資料皆空時顯示對應「尚無…」文字且不拋例外，皆有測試覆蓋並實測通過。
- **規格列出的測試案例**：chartSync.test.ts（5）、chipMath.test.ts（7，涵蓋規格 5 條再加分拆）、ChartStack.test.tsx（8，對應規格 #11–18）、ChipTab.test.tsx（9，涵蓋規格 #19–23）、StockPage.test.tsx（9，含規格 #24–29 與 M1 回歸）逐一核對存在且斷言正確。
- 後端測試、`m2_verify.sh`、`docker compose config` 均為回歸通過（T2-8 未動後端與 compose）。
