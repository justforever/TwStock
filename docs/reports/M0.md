## 5. M1 建議

M1 的目標應該是**日 K 線**：`daily_price` 時序表 + TWSE/TPEx 日成交資料 ETL + 歷史回補 + `/api/stocks/{id}/prices` + 前端 K 線圖。建議切成六個任務：

| 任務 | 內容 | 重點 |
| --- | --- | --- |
| T1-1 | migration 0002：`daily_price(stock_id, trade_date)`、`etl_job_log` | `daily_price` 用 `create_hypertable_if_available()`（有 TimescaleDB 才轉），`etl_job_log` 記每次 job 的來源、區間、筆數、耗時、結果。價格一律 `NUMERIC`，成交量單位「股」。 |
| T1-2 | 日成交 parser | TWSE `STOCK_DAY_ALL`（全市場當日）與 `STOCK_DAY`（單檔整月，回補用）、TPEx 對應端點。要處理「除權息當日」「無成交（`--`）」「千分位逗號」「`X` 註記」。fixture 一樣手寫。 |
| T1-3 | loader + job + 回補腳本 | `ON CONFLICT DO UPDATE`；回補以 `trading_calendar` 為準，只抓開市日；對來源加節流（TWSE 建議 ≥3 秒一次請求），失敗寫 `etl_job_log` 並可續跑。 |
| T1-4 | API `/api/stocks/{id}/prices?from=&to=&limit=` | 預設回最近一年，上限明確；回傳格式直接對齊 Lightweight Charts 的 `{time, open, high, low, close}` + `volume`。 |
| T1-5 | 前端個股頁 K 線 | 把 `/stock/:id` 占位頁換成真的：Lightweight Charts、日／週／月切換、成交量副圖。 |
| T1-6 | 排程整合 + 回歸驗收 | 盤後（台北 15:00 之後）抓當日，補 `m1_verify.sh`。 |

### M1 風險

| 風險 | 說明 | 緩解 |
| --- | --- | --- |
| **R-1 來源格式仍是黑盒** | 承 U-1，M1 要碰的端點更多（日成交、還原權值），全部只能靠手寫 fixture。fixture 寫錯的成本在 M1 比 M0 高（欄位語意錯會產生錯誤的價量資料，且會被寫進 DB）。 | 每個 parser 都要有「欄位數 / 標題列」的硬檢查，不符就丟 `SourceFormatError` 而不是猜。上線前先請使用者在 Mac 上跑一次單日抓取並人工核對 2330 的 OHLCV。 |
| **R-2 回補會被來源限流／封鎖** | 歷史回補動輒上千次請求，TWSE 對高頻請求會回 5xx 或直接斷。 | T1-3 一定要做節流 + 指數退避 + 斷點續跑（靠 `etl_job_log`），且預設回補區間要短（例如一次一年），不要寫成「一鍵抓十年」。 |
| **R-3 沒有 TimescaleDB 時效能** | 使用者用 Compose 會有 TimescaleDB，但開發環境沒有，兩邊執行計畫不同，效能問題在開發環境測不出來。 | `daily_price` 除了 hypertable 外，一律建 `(stock_id, trade_date DESC)` 的一般索引，確保無 Timescale 時也夠快。查詢一律帶 `trade_date` 範圍。 |
| **R-4 除權息與還原股價** | 原始收盤價未還原，畫長期 K 線會有跳空；還原需要除權息資料（M2 才做）。 | M1 明確只存「未還原原始價」，欄位命名寫清楚（`close` 而非 `adj_close`），API 也標明。還原留到 M2 有股利資料後再加 `adj_*` 欄位，不要在 M1 硬做。 |
| **R-5 資料量與備份** | 2,000 檔 × 250 交易日 × 10 年 ≈ 500 萬列，加上 M2 的籌碼會更多。目前 Compose 只有一個 named volume，沒有備份機制。 | M1 收尾時加一支 `scripts/backup.sh`（`pg_dump` 到 `data/`），並在 README 寫明備份與還原步驟。 |
| **R-6 排程與交易日判斷** | 盤後 job 若在非交易日跑會抓到空資料或前一日資料重複寫入。 | job 開頭先查 `trading_calendar`，非開市日直接跳過並寫 `etl_job_log`；這也順便驗證了 M0 的交易日曆有沒有用對。 |

### 進入 M1 前的前置條件

1. 使用者在 Mac 上跑一次 `docker compose up -d --build`，確認五個 service 起得來、`migrate` exit 0、`\dx` 看得到 `timescaledb`（解掉 U-2、U-4）。
2. 使用者跑一次真實來源的 `load-stocks`（上市、上櫃）與 `load-calendar`，回報筆數；若格式不符先修 parser 與 fixture（解掉 U-1）。
3. 上述兩點確認後再開 M1 規格；否則 M1 會疊在一個未驗證的基礎上。
