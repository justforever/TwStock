### 問題清單

#### Blocker

1. **`web/src/components/CandleChart.tsx`（第 100–160 行左右，資料更新用的第二個 `useEffect`）：每次資料變動都疊加新的 series，從不移除舊的，導致「還原價切換」「切換區間」在畫面上並未真正取代資料，而是把新舊 K 線／均線／成交量全部疊在同一張圖上。**

   目前程式碼結構：

   ```tsx
   useEffect(() => {
     ...
     const candlestickSeries = chart.addCandlestickSeries({ ... })
     candlestickSeries.setData(...)
     maPeriods.forEach((period, idx) => {
       const lineSeries = chart.addLineSeries({ ... })
       lineSeries.setData(...)
     })
     const volumeSeries = volumeChart.addHistogramSeries({ ... })
     volumeSeries.setData(...)
   }, [bars, maPeriods])
   ```

   這個 effect 依賴 `[bars, maPeriods]`，而 `chart` / `volumeChart` 是透過 `useRef` 在第一個 `useEffect`（`[]` 建圖表）裡建立、跨渲染保留的**同一個圖表實例**。規格要求「`useEffect` 依 `[]` 建立圖表、依 `[bars, maPeriods]` 更新資料」——「更新資料」的意思是同一組 series 呼叫 `setData` 覆蓋，但目前實作是每次都呼叫 `chart.addCandlestickSeries(...)` / `chart.addLineSeries(...)` / `volumeChart.addHistogramSeries(...)` **新增一組全新的 series**，舊的那組從未 `series.remove()` 或用 ref 保留起來覆寫，等於是把新資料疊加畫在舊資料上面，而不是取代它。

   實測驗證（用同樣的呼叫順序模擬 3 次資料更新，如同「掛載一次 + 切換還原價一次 + 切換區間一次」）：

   ```
   candleCount: 3, lineCount: 9, volCount: 3
   ```

   也就是說使用者只要：
   - 進入個股頁（第 1 次資料更新）
   - 勾/取消勾選「還原價」（第 2 次，`adjusted` 變動觸發重新 fetch → `bars` 變動）
   - 再點一次區間按鈕（第 3 次）

   畫面上就會同時存在 3 條 K 線、9 條均線、3 條成交量柱，互相重疊，使用者實際上**看不出「還原價切換是否真的改變資料」**——因為未還原的舊 K 線仍然畫在圖上，只是被新的蓋住一部分，而非被取代。這正好是本輪審查要點「還原價切換是否真的改變資料」的核心風險，且屬於使用者可直接觀察到的功能性錯誤。

   為什麼測試沒抓到：`StockPage.test.tsx` mock `lightweight-charts` 時，`addCandlestickSeries` / `addLineSeries` / `addHistogramSeries` 都回傳**同一個** `series` 物件，且測試也沒有斷言呼叫次數，所以看不出重複建立的問題。

   **建議修法**：把三種 series 用 `useRef`（例如 `candlestickSeriesRef`、`lineSeriesRefs`、`volumeSeriesRef`）保存，在第一個（建圖表的）`useEffect` 裡只建立一次；第二個 `useEffect`（依 `[bars, maPeriods]`）只呼叫既有 series 的 `setData(...)`。若 `maPeriods` 的數量或內容改變導致均線條數需要增減，才需要在該 effect 內先 `series.remove()` 舊的均線 series 再重建對應數量。
