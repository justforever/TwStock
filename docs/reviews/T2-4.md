### 其他觀察（非 blocker/major，建議 nit，不影響本輪結論）

1. `find_field_all` 內部先掃「欄位名不含括號」再掃「含括號」的兩階段優先序，是規格沒有要求的額外邏輯。以目前 8 個 fixture 驗證皆正確（因為真實欄位大多本來就帶括號），且沒有造成任何測試失敗，但這段邏輯的必要性沒有註解說明，日後如遇到「同時有裸欄位與括號欄位且都符合 tokens」的真實資料，優先序是否符合預期沒有測試覆蓋。建議 T2-5 沿用 `find_field_all` 時，若遇到需要用到此優先序的情境，補一個對應測試或拿掉這段多餘邏輯，簡化成單一迴圈。
2. `institutional.py` 幾處 `f"...沒有插值..."` 的字串（如 `f"TPEx 回應不是 JSON 物件"`、`f"新版 TPEx 法人端點表格不符，改用舊版"`）其實不需要 `f` 前綴（lint 上是 F541 no-op f-string），純風格問題。
3. `fetch_twse_institutional` / `fetch_tpex_institutional` 內建構 `params` 字典的程式碼在 `client is None` 與 `client is not None` 兩個分支重複了一次（`fetch_twse_institutional` 尤其明顯），可以在 `try/finally` 外先組好 `params` 再分支，減少重複，純可讀性建議。

以上三點都是風格 / 可維護性建議，不影響正確性與驗收標準，不列為 blocker 或 major。

無 blocker、無 major。三大法人上市／上櫃（含舊版備援）parser 與 `find_field_all`／`find_field_all_optional` 的行為與規格逐項核對一致，測試齊全且自跑全部通過，`M2-chips.md` §1.4 允許改動的檔案範圍未超出。
